The [**skill-2026.10** release](https://github.com/IoTone/poplog/releases/tag/skill-2026.10) of the Poplog runtime and the `pop11` Claude skill is out, and the headline is platform coverage: the August release carried macOS arm64 and Linux x86_64; this one adds **Linux aarch64** (Raspberry Pi 5 class) **and Linux riscv64** — the two ports the [revival project](/news/2026-07-24-poplog/) set out to deliver. One line installs it anywhere:

```sh
curl -fsSL https://raw.githubusercontent.com/IoTone/poplog/master/tools/install-skill.sh | sh
```

## The bug worth telling

Every engine in this release is bootstrapped from a **re-blessed `corepop` seed** (`corepops-2026.10`), and the reason is a good story. The three non-x86 seeds each predated their platform's `struct STATB` layout fix. That mattered more than it sounds: `poplibr`, the library tool, is a symlink to `corepop`, so the librarian stamped library members with dates read through the seed's *wrong* struct offsets — a library built in the afternoon would list as 1996. On top of that, `sys_file_stat` was returning `st_blksize` where `file_size` should be and the mtime *nanoseconds* as `file_mtime`; the Z-machine test suite failed outright on both new boards and now passes 100/100.

The test harness got stricter too: a suite that prints a green summary and then dies no longer counts — the verdict is `ALL PASS` *and* engine exit 0.

## Built and verified on its own hardware

Every tarball comes from a clean bootstrap on the platform's own silicon: engine rebuilt from the seed, the self-test gate green, then the package unpacked into a sandbox `$HOME`, installed, and smoke-tested through both the **MCP and LSP** protocols. Downloads are all near 2 MB — the engine, `pop/lib` as source, the skill, both protocol servers, and the story files.

The release also carries edition 1.9 of [*Pop-11 and the Robot Army*](/news/2026-09-10-pop11-and-the-robot-army/), with the cheat sheet now covering chapter 8's examples.
